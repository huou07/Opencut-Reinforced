## Commands

Local scaffolding under the gitignored `apps/or_app/build/local-deb/` drives the
steps; each step calls a tracked repository script or the workflow's own
arguments. The equivalent command sequence is:

```sh
# 1. pinned codec sources (libvpx, libopus) — tracked script
PATH="<nasm-prefix>/bin:$PATH" bash scripts/build_desktop_export_codecs.sh \
  linux <work>/codecs-install <work>

# 2. FFmpeg 8.1.3 shared libraries, LGPL posture, with the workflow's
#    FFMPEG_COMMON/HELPER/EXPORT_CONFIGURE_ARGS appended in that order
./configure --prefix=<work>/ffmpeg-install <args> && make -j8 && make install

# 3. Flutter Linux bundle against that prefix. The native-assets hook runs
#    semi-hermetically, so FFMPEG_DIR and PKG_CONFIG_PATH must arrive through
#    $HOME/.cargo/config.toml (below), and OR_PACKAGED_MEDIA_RUNTIME_DIRECTORY
#    seeds the media runtime the project CMake hook installs.
(cd apps/or_app && flutter build linux --debug)

# 4. stage the helpers/libraries beside the bridge and patch them to $ORIGIN,
#    exactly as the hosted "Package FFmpeg beside the desktop probe" step does
bash scripts/stage_codec_licences.sh stage <bundle> <FFmpeg-COPYING> <codec-notices>
bash scripts/stage_codec_licences.sh verify <bundle>

# 5. package and install into a disposable root
bash scripts/package_linux_deb.sh <bundle> out.deb "$(git rev-parse HEAD)"
dpkg-deb --extract out.deb <root>

# 6. the hosted packaged journey, with the installed payload as its media runtime
OR_PACKAGED_HELPERS_DIRECTORY=<root>/opt/opencut-reinforced \
OR_PACKAGED_BRIDGE_DIRECTORY=<root>/opt/opencut-reinforced/lib \
OR_PACKAGED_MEDIA_RUNTIME_DIRECTORY=<work>/or-packaged-media-runtime \
  python3 scripts/run_packaged_desktop_journey.py
```

`$HOME/.cargo/config.toml` used for step 3 (the local `$HOME` is a
project-local directory because the shared account's `$HOME` is not writable
by this worker):

```toml
[build]
jobs = 4
rustflags = ["-L", "native=<work>/ffmpeg-install/lib", "-C", "link-arg=-Wl,-rpath,$ORIGIN"]

[env]
FFMPEG_DIR = { value = "<work>/ffmpeg-install", force = true }
PKG_CONFIG_PATH = { value = "<work>/ffmpeg-install/lib/pkgconfig:<work>/codecs-install/lib/pkgconfig", force = true }
```

## Local failures found, and what fixed them

1. **The native-assets hook reused a bridge built against the system FFmpeg.**
   Debian 13 ships FFmpeg 7 development libraries (`libavutil.so.59`), and the
   first build produced a bridge linked against them with no RUNPATH. Two
   independent causes:
   - Flutter runs build hooks in a semi-hermetic environment; only `PATH`,
     `HOME`, the temporary/proxy variables and a small tool allowlist reach the
     hook. `FFMPEG_DIR` cannot be exported into it, which is why the hosted job
     writes `$HOME/.cargo/config.toml`.
   - Even with the search path present, `/usr/lib/x86_64-linux-gnu` was searched
     first, so the linker still chose the system `libavutil.so.59`. Pinning
     `-L native=<prefix>/lib` in `[build] rustflags` puts the pinned prefix
     first; the rebuilt bridge then linked `libavutil.so.60`.
2. The hook caches its output and does not invalidate it when the pinned FFmpeg
   changes; the bridge cache has to be cleared before a rebuild, exactly as
   `AGENTS.md` records for the shared hook cache.

Neither is a product defect; both are local-host build conditions that any
future local `.deb` build on this host will hit, so they are recorded here.

## What this does not establish

- **Not hosted or CI-parity evidence.** Flutter 3.47.7 here versus 3.47.5 in
  CI, and a locally built FFmpeg rather than the hosted job's staged artifact.
  `docs/QUALITY.md` keeps packaged and native acceptance with GitHub Actions.
- **No `apt` install, upgrade or purge.** This host has no `sudo`, so
  `scripts/test_linux_deb_install.sh` (real apt install directly and inside
  ubuntu:24.04 / debian:13-slim containers) was not run. The install evidence is
  an extraction into a disposable root plus a launch from that root; dependency
  resolution by apt, package upgrade and purge are still hosted-only.
- **The packaged journey's Flutter/Dart entrypoint is the integration-test
  build**, not the packaged `kernel_blob`. The native payload under test
  (`or_app` shell, Rust bridge, `ffmpeg`, `ffprobe`, all `libav*`/`libsw*`) is
  byte-identical to the installed package, as tabulated above.
- **No timeline trim/razor cut in this journey.** The packaged journey performs
  create, import, unsupported-import rejection, timeline insert, title overlay,
  preview play/pause, rename, save, close, same-process and post-restart reopen,
  export over an existing destination, re-import of that export onto the
  timeline after the source clip, relink preserving `MediaId`, and the
  missing-source / missing-probe / bad-project failure paths. Timeline trim
  coverage lives in the hosted Flutter widget lane
  (`apps/or_app/test/widget_test.dart`), which is `UNVERIFIED` on this host
  because the native-assets hook cannot fetch its Rust components.
- **One host, one architecture.** amd64 Debian 13 only; no physical-device,
  macOS, Windows or Android claim, and no performance claim — this journey is
  a correctness run, not a benchmark.
- It does not publish anything: no tag, no release, no artifact upload.
